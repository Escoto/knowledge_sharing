1. Purpose

This page tells you how to use the example_setting setting.

Use this setting when a value must go into the URL, but must not go into the request body.

TermMeaning on this page
RowOne record from the source table.
FieldOne column value in a row.

2. The problem

The service needs the record ID in the URL. The request body must not contain the ID.

endpoint
/api/v1/records/{record_id}/actions/approve
!

Do not remove record_id before the job makes the URL. If you do this, the job stops with an error.

3. How the data moves

The diagram shows the steps for each row. The text on the right tells you what occurs and why the step is in that position.

Step 1
Read table
sales.orders
The job reads the rows first, because all the next steps use these rows.
Step 2
Map columns
record_idstatusinternal_note
The mapping removes the columns that the API does not use, but it keeps record_id for step 3.
Step 3
Make the URL
…/records/R001/actions/…
The job puts the record_id value into the URL, so this step must occur before the job removes the field.
Step 4
example_setting
record_idstatus
The job removes record_id from the body last, because the URL already contains the value.

The column names are examples. R001 is an example value.

✓

Summary. Remove a field in the mapping when the API never needs it. Use example_setting when the URL needs the field, but the body does not need it.

4. Rules

  • Put example_setting in the push section.
  • The value is a list of field names.
  • Each field in the list must be in the row. If a field is not there, the job stops.
?

Library version. Use version 2.0 or a later version. An older version does not accept this setting.

5. Procedure: add example_setting to a config

Before you start

  • Make a new branch from main.

Steps

  1. Open the config file.

  2. Add example_setting below method. The green lines are the new lines.

    config.yml
      push:    endpoint: "/api/v1/records/{record_id}/actions/approve"    method: "POST"    example_setting:      - "record_id"    # ... the other settings do not change ...

  3. Save the file. Commit the change. Open a pull request.

6. Check the result
